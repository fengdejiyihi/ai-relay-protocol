# ADR-011 按成交价抽成的盈利模式

- 状态：已定（部分取代 ADR-008 里「fee 由供给方在清单里定」的做法）
- 日期：2026-11-05（2026-11-06 补第 4 条推广期订单免费、第 5 条透支额度）

## 背景

原来每个收费动作的手续费是供给方在清单里自填的固定 `fee`（¥1–¥100 / 笔），只读查询一律免费，没有入驻费。这和「按效果计费」不一致：同样一笔成交，¥20 的理发和 ¥5000 的外包收一样的钱；定价权也在付费方手里。

## 决定

全部只向供给方收，从预付余额里扣，Relay 不碰用户的钱。三块：

1. **订单类：按成交价抽成。** 手续费 = 成交价（订单的 `amount`）× 平台费率，默认 3%，四舍五入到分。失败、取消、过期照旧免收（ADR-005 的冲正规则不变）。
   - 多方案的单以用户选定方案的报价为成交价：按完成计费、按成交价抽成的单在选方案时按方案报价 × 建单时的费率重算，方案没写报价的按预算算；每次都从快照算，不从订单当前的手续费推。`on_accept` 的单接单时已按预算扣过，不再改；没有成交价（按固定 `fee`）和只读（按查询单价）的多方案单也不随方案报价变。
   - 选方案让手续费变高时，供给方的可用余额（余额 − 其他在途单的手续费）要够新的手续费，不够就不发这次选择：下发时预留的是按预算算的钱，不核对的话完成时会扣到没预留过的钱、把余额扣成负数。选择没生效、已选方案被撤回时，手续费回到「预算 × 费率」，只降不升（往上调要重新核对，留给下一次选方案）。
   - 选择发出后、Relay 记下供给方的答复之前供给方撤回了同一个方案：以 Relay 收到的答复为准。答复 `selected` / `completed` 照常生效，方案恢复成已选，按这个方案的报价收；答复 `failed`，或者 Relay 没收到明确答复（超时、5xx）时方案保持撤回，手续费回到预算价，这个方案不会再被选定：回调报来的写着它的方案号的 `completed` 不成交（补拉路径还不核对方案号），不写方案号的会被当成用户另选方案的结果（所以多方案单的 `completed` 要写方案号，撤回了的方案的 `completed` 要丢掉、补拉时也别再报），供给方要用新的方案号重新提交。等答复期间被拒的回调（方案号对不上、还没选方案）、补拉时被拒的 `completed`（还没选方案）不是对选择的答复，选择仍算在路上（回调、补拉、超时取消、再次选方案用的是同一个判定），不然一条被拒的回调就能让撤回把手续费退回预算价，答复到了却按这个方案成交。答复 `selected` / `completed` 落库、这个方案是订单的已选方案时，手续费按发出选择时为它定的数收（那时核对过余额）：等答复期间被退回预算价的（答复晚过在途时限，撤回或补拉已经把它退回）在这里改回来，不再核对余额。答复落库晚过在途时限（Relay 自己耽搁了；供给方答得慢的，网关按没收到答复处理）、其间用户又选了别的方案的：答 `completed` 的，订单还没按改选的方案结束时照样按这个方案当场成交、按它收（改选的方案退回可选，改选的更贵时手续费往下改）；答 `selected` 的，改选的方案还标着已选（生效了或还在等答复）时以改选的为准，这个方案不恢复、不按它收，改选没生效的，这个方案恢复成已选、按它收。和这次选择交叠的补拉（选择发出到答复落库之间发出或回来的）拿到的方案列表里暂时没有选择涉及的方案，不按撤回处理。选择发出后进程中途退出、答复没落库的，过了在途时限由补拉把手续费退回预算价（订单上没有已选方案时），不会一直多占可用余额。
   - 清单没有成交价（`amount: "none"`）的收费动作没有基数可乘，仍按清单里的固定 `fee` 收，P-FEE-1 的 ¥1–¥100 范围只约束这一种（只读动作不算，见第 3 条）。
   - 单个供给方可以设有期限的优惠费率（武汉本土首批商家第一年 1%），到期自动回到平台费率。优惠只往下优惠：后台设的时候要低于平台费率，之后平台费率调得比它还低时按平台费率（取两者低的）。Relay 自营的沙箱是长期 0%。
2. **入驻费：** 个人开发者 ¥30、商家 ¥300，首次审核通过时从余额扣，每个账号只收一次（注销重开不再收）。免入驻费的推广期开关打开时全部免收，推广期内通过的以后也不补收。入驻费按送体验额度之前的余额判断，体验额度不能抵。
3. **查询类：按次。** 只读动作（`readonly: true`）每次成功返回扣一次，单价平台定，0 表示不收（上线时为 0）。清单里的 `billing`、`fee` 对只读动作不起作用，审核也不检查它的 `fee`。
4. **推广期订单免费。** 平台开着这个开关时，新建的订单（按成交价抽成的、按固定 `fee` 收的）和查询都不收手续费，余额是 0、是负数也照样进搜索、能接单，也不提示余额偏低。和入驻费的推广期开关分开管，上线时默认开着。按建单时快照：推广期里建的单，关掉推广期以后也不补收，多方案单之后选方案也按 0 算；推广期开始前建好的单照建单时的手续费收（还在等确认的，确认时余额不够照样不下发）。收费动作照样在计费点记一条 0 元流水，查询不记。
5. **透支额度（2026-11-06 定：统一 ¥50，后台可改）。** 余额用完以后供给方还能再接这么多手续费的单，余额会变成负数，下次充值先补上。所有搜索门槛、下发前核对、选方案改价都按**可用额度** = 余额 − 还没结算的订单占着的手续费 + 透支额度 算（还没结算 = 已下发；或按完成计费的已接单、方案待选）。起因是商家看到余额还有、新订单却因为在途单占满被拒，会以为是故障：页面上把可用额度和余额并排写、写明暂停接新单不是故障，可用余额低于提醒线或开始透支时提醒一次，可用额度用完时再提醒一次（先只发邮件，短信以后再做），订单列表里被拒的单写原因。透支额度对所有供给方一样，0 表示不透支，上限 ¥10000；调小当场生效。

费率、查询单价、入驻费两档、两个推广期开关（订单和查询免手续费、免入驻费）和透支额度是平台的一份设置，管理后台「计费设置」修改并记审计。建单时把手续费和当时的费率快照进订单，之后调价不影响在途订单。

搜索门槛随之改（推广期订单免费开着时一律为 0）：成交价从输入里取的动作事先不知道这一单要多少，余额 > 0 就进搜索（这个供给方此刻的费率是 0 的不要求余额，平台费率调成 0 也一样）；成交价写死在清单里的要够一笔的手续费，至少 1 分（多方案单选方案时还会按方案报价重算，写死的成交价算出来是 0 也不等于不收费）；按固定 `fee` 收的要够一笔；查询类要够单价（以上的「余额」都指可用额度，见第 5 条）；门槛为 0 的动作不看余额，余额被扣成负数也照常。下发前仍按这一单的实际手续费核对可用额度。门槛只拦新建的单：同一 `request_id` 的重放（AI 重试取结果、带确认码确认）拿回原单，不按此刻的门槛拦，下发前按这一单建单时的手续费核对（和网页确认一样），推广期里建的单推广期结束后照样能确认、能取回结果。

协议字段不变：`fee` 保留（没有成交价时生效），`amount` 多了「抽成基数」这层含义。

## 后果

- 收入和成交额挂钩，供给方不再自己定价；供给方的接入代码不用改。
- 收费动作最好写上成交价字段，否则只能按固定 `fee` 收。
- 多了一份计费设置，供给方多了类型、优惠费率、入驻费结清记录。上线时已经审核通过过的供给方记为入驻费已结清（免收），Relay 自营的沙箱设成长期 0%。
- 免入驻费的推广期结束后，为付入驻费充的钱不算「真正充过值」：余额全是体验额度时不提示余额偏低（体验额度以外的充值扣掉入驻费后还有剩才算充过值）。
- 入驻费记一条 `adjust` 流水（备注「入驻费（个人开发者 / 商家）」），不是订单扣费，不进争议。
- 有透支额度后余额最低到 −透支额度：已下发的单下发前占好了手续费，完成时照常扣；之后调小透支额度、管理员扣回余额时余额可能更低，这些供给方的收费动作当场隐藏，等充值补上。
- 余额提醒按可用额度算：占用只在新订单发出时变多，做完扣费时余额和占用一起减、可用额度不变，订单正常做完不会来回发信。订单失败、取消让占用变少时档位会回落、下一单又跌回去，所以没充过值的回落要等记录满 24 小时才降档：同一档或更低档的邮件一天最多一封，升档、充值后再跌破照常马上提醒。邮件只发给上线中的供给方（暂停中的充了值也接不到单，和后台页面一样不说「充值后恢复」）。
- 余额是负数就是欠着透支的手续费：供给方自己不能带着欠款注销（注销后不能再充值，等于把欠款带走），要先充值补上；管理员可以注销，确认框写明欠多少。一个账号最多 10 个供给方、每个都要审核通过才有透支额度，靠开新供给方反复透支的风险有上限，后台供给方列表能看到各家的可用额度。
